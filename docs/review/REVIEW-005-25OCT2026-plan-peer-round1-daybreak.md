- [SEVERITY blocker] D4.3/D5.2 — The relay requires the target to fetch code and automatically upload results, directly conflicting with CLAUDE §9’s prohibition on auto-upload/phone-home. It is also described as loopback-bound, which makes it unreachable from remote targets; one token permitting two GETs plus a POST is not single-use. — Eliminate target-initiated result uploads, capture output through the selected transport, and declare full-script execution unsupported where it cannot fit safely. If any relay remains, use an explicitly reachable non-wildcard interface and separate one-use download/upload capabilities.

- [SEVERITY high] D1.1 — The global negative guard can suppress real findings. The exemption misses the Unicode-dash fixtures and `Test-CoercedAuth.ps1`’s “enabled via NtAdjustToken” form; blanket `STATUS_ACCOUNT_DISABLED` suppression can also hide account-enumeration evidence. It additionally prevents operator `--severity-rules` from intentionally grading such lines. — Make suppression marker-and-rule-aware, cover all standalone/bulk emitters, preserve explicit custom-rule matches, and test the complete graded miss/log corpus.

- [SEVERITY high] D1.2 — “Longest literal pattern text” is not a valid measure of regex specificity: alternations, anchors, optional groups and long generic expressions can outrank narrower rules or conceal shadows. — Give built-in rules stable IDs and explicit priorities/expected severities; audit every sample against those expectations and allowlist intentional overlaps by rule ID.

- [SEVERITY high] D1.4 — Dedup on `(host, service)` plus containment/Jaccard can merge distinct ports or facts. Keeping ports and paths as whole tokens does not prevent merging when one differing token among many still yields Jaccard ≥0.75. — Require compatible port/protocol attribution and equality of protected-token sets, use one-to-one matching, and limit fuzzy transforms to known dispatcher wrappers. Add same-host/different-port and same-path/different-secret tests, plus the omitted SMB-shares fixture assertion.

- [SEVERITY medium] D1.5 — `no_root_squash` becomes critical only in `_DEFAULT_RULES`; `_BULK_RULES` still grades it high first, so identical evidence receives different severity by layout. The proposed shadow gate does not explicitly audit the composed bulk rule lists. — Update the bulk rule and run shadow/exact-severity checks against every actual composed rule order.

- [SEVERITY high] D2.1 — Reclassifying a truncated display line with a second, first-match regex system can drift from the severity rule that created the finding and attach incorrect remediation. A fixture-only 10% ambiguity threshold knowingly permits misclassification, while deleting a KB class may simply fall through to an overlapping class. — Attach a stable built-in rule/class ID during classification while retaining tuple compatibility for custom rules; require exact sample-to-`kb_id` expectations and zero unexplained ambiguity across the full corpus.

- [SEVERITY high] D2.2 — AD “chain” hints correlate findings across the entire run before domain identity exists, so signing, coercion and ESC8 findings from unrelated hosts or domains can be presented as one attack path. — Require same-domain and role-compatible correlation, or label these as uncorrelated signals until S3 supplies structured domain identity.

- [SEVERITY high] D1.6/D3.3/D3.5 — `collect() -> list[dict]` cannot carry PASS/INFO/NA/ERR posture observations or domain rollups to both report and dashboard. A directly invoked dashboard would therefore lack posture unless it relies on a prior report side effect; `aranum.py` also copies only findings/report artifacts, not `posture.json`. — Return a structured collection result containing findings, posture and diagnostics; have both consumers use it, and copy/document `posture.json` in session reports.

- [SEVERITY medium] D3.1/D3.3 — The pipe protocol does not define escaping, detail newline normalization, duplicate-ID handling, or malformed `POSTURE|` behavior. Malformed posture output could fall through to normal severity rules and become a false finding. — Define an ASCII escaping/framing scheme, strict anchored parser, duplicate detection, and quarantine all malformed `POSTURE|` records as diagnostics rather than classifying them.

Disabled roastable accounts, DC exclusion for unconstrained delegation, recursive group membership and signed `LargeInteger` password ages are all likely fidelity failures. — Factor filters/converters into testable helpers and add fixtures asserting disabled-account exclusion, DC exclusion, recursive membership semantics and correct AD interval conversion.

- [SEVERITY high] D3.3 — Domain checks become host findings before rollup, so the same domain policy failure is counted once per observing host while `posture.json` separately claims one domain rollup. Parsing `domain=` from prose and retaining all observers without per-observer results also loses conflicts and errors. — Store structured domain/observer fields, preserve every observation, define the status lattice including ERR, and emit one canonical domain-scoped finding for KPIs.

- [SEVERITY high] D3.4 — Appending two PowerShell advanced scripts is not valid: the second script’s `[CmdletBinding()]`/`param` block is no longer at the beginning of a script and can fail parsing under PowerShell 5.1. — Transport a wrapper that invokes each collector as a separate scriptblock, and test the exact combined payload under the 5.1 compatibility parser.

- [SEVERITY high] D4.4 — Adding names to `_AUTO_ENUM_VALUE_FLAGS` does not partition arguments. Without a dedicated split, `--local`, `--transport`, relay and desktop options will be forwarded to `auto-enum.sh`, which rejects them, while shared credentials may be routed inconsistently. — Parse `aranum run` into explicit auto-enum and local-enum argument sets, define shared-option propagation, and test the final argv for both subprocesses.

- [SEVERITY high] D4.4 — The proposed nested `<out>/{linux,windows}/<host>` layout is incompatible with current binary bulk detection. Dashboard inventory and `mode`/`per_host` semantics are also undefined. — Implement an explicit mixed-root collector that excludes bulk roots from service traversal, rebases evidence paths, combines coverage/verdicts, and defines a schema-v2-compatible mode/layout representation.

- [SEVERITY high] D5.1 — Linux RDP is not implemented: falling through from xrdp to SSH or VNC does not provide the required Linux RDP pathway and cannot handle an xrdp-only host. — Add a real xrdp-assisted transport, or reduce the stated acceptance target and M8 count.
