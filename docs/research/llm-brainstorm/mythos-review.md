## Part C — Verdict

The recommendation is sound in shape: dev-time compilation into deterministic artefacts (C) first, a local-only sidecar (A) second, inline enrichment (B) rejected on reproducibility grounds, and the egress tier as the binding axis. It is not yet sound in its premises. The draft's safety argument for every T2-eligible idea and for the validator rests on `rule_id`, `kb_id` and class titles being repo vocabulary, and that is false today: critical-floor fallbacks slug target-controlled text into `rule_id`, top-risk grouping falls back to target-derived titles, and the Redactor is off by default and never touches ids. Two measured baselines (16 vs 29 ungraded hits; the fixture ratios) also do not reproduce from the harness, which undermines the "[M]" provenance discipline the document otherwise does well. The single most important challenge the author must answer before any code is written is: **define "vocabulary id" precisely (present in `finding-kb.json` classes or the compiled rule list, `kb_match == "rule"`), show by measurement how much of a real run falls outside it, and specify what the advisor does with the remainder.** Until that is settled, no idea in the catalogue is T2-eligible, the validator's "id must exist in input" control is bypassable by planting lines, and LLM-05/06/10/12 should be re-tiered to T1 with full redaction of every serialised string including keys.
